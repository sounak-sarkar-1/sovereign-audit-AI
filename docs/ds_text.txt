Agents must apply this document when building or modifying any frontend code. Replaces Visual design guidance in UI Spec documents (UI_Admin, UI_Manager, UI_Auditor, UI_Client). Those documents remain authoritative for screen layout and component behaviour. This document is authoritative for all visual styling. Version v1.0 — March 2026   Table of Contents 1. Design Philosophy Sovereign Audit AI follows a modern light-canvas SaaS design language. The core principles are: Light and airy — the page canvas is warm off-white (#f2f0ee). Cards float on it using shadow, not border. Rounded and soft — everything from cards to buttons to inputs uses generous border-radius. Hard rectangular edges are eliminated. Colour as accent, not structure — the brand purple palette is used for active states, highlights, and key actions. It is not used as heavy fills on structural chrome like sidebars. Information density is controlled — tables and lists have room to breathe. Alternating row shading is replaced by hover states only. Hierarchy through typography and weight — section headings rely on size and weight, not background fills or underline borders.  Agent instruction: When implementing any component not explicitly described in this document, default to the principles above. Prefer rounded, prefer light fills, prefer shadow over border.  2. Page section headings (H1 role) are plain text — no background fill, no underline border. Weight and size alone create hierarchy. Audit IDs and reference codes (e.g. AUD-047) always use the mono style in a grey pill chip, never inline body text. Do not use all-caps for any text except keyboard shortcut labels (e.g. ⌘K). Truncate long strings with ellipsis (text-ellipsis overflow-hidden whitespace-nowrap) and show full value in a Tooltip on hover.  4. Agent Implementation Instructions These are explicit instructions for the Antigravity agent when implementing or modifying the frontend using this design system. Rule # Instruction 1 Before writing any frontend component, check this document for the exact class specification. Do not improvise border-radius, shadow, or colour values. 2 Never use hard-coded hex values in JSX or TSX. Always use Tailwind tokens defined in tailwind.config.ts. If a colour is not in the config, add it to the config first. 3 Never use rounded-none or the default Tailwind rounded (4px) on any visible surface. Minimum radius: rounded-sm (6px). 4 Never use alternating row shading on tables. Apply hover state only (hover:bg-[#faf9f8]). 5 The sidebar background is bg-white in light mode. No rectangular buttons anywhere on the platform. 7 Cards have no visible border by default. shadow-card replaces the border. Only exception: alert cards which have a left border accent. 8 Status badges are light tint + matching text (§7.5). Never filled with a solid colour. 9 All tabs use the pill style from §7.6. No underline tabs anywhere on the platform. 10 For every list, table, and board column: implement the empty state per §8.4 before moving on. 11 Implement all transitions per §8.1. Every interactive element must have a hover and focus state. 12 The user card at the bottom of the sidebar (§7.1.1) must use the gradient banner — this is a key brand moment. 13 Every Kanban audit card must include the Audit ID chip in mono style at the top. Generate the ID from the audit&apos;s uuid — use the last 6 characters, prefixed with &apos;AUD-&apos;. 14 Dark mode must be implemented for every component. Test both modes before marking a component done. 15 Load the Inter font from Google Fonts by adding the @import to globals.css. Set it as the default sans font in tailwind.config.ts.
