2. Flow 1 — Gen AI Scope Extraction from SOP Upload
2.1 Overview
This flow covers the asynchronous process by which a Manager uploads an SOP or manual document and the platform uses the configured Gen AI model to extract a draft list of audit scope line items for Manager review. The flow uses pg-boss for background job processing to avoid HTTP timeout on long-running AI calls.
Attribute
Value
Trigger
Manager clicks 'Extract Scope' after uploading a PDF/DOCX document
Preconditions
Audit exists with status=draft; at least one BU selected; active AI model configured
Primary Actor
Manager
Async / Sync
Asynchronous — returns job ID immediately; client polls for completion
Success End State
Draft scope line items displayed in editable table for Manager review
Failure End State
AI job fails; error shown with option to retry or use alternative scope method
2.2 Step-by-Step Flow
Step
Actor
Action / Event
System Response / Notes
1
MANAGER
Selects BU from dropdown and uploads PDF/DOCX file (max 10 MB) via file dropzone
UI validates file type (PDF/DOCX) and size client-side before upload
2
UI → API
POST /manager/audits/:id/scope/extract-from-document (multipart/form-data: file + auditBusinessUnitId)
API receives request; validates JWT + role=manager + audit ownership

If no active model: return 503 AI_UNAVAILABLE immediately. Else continue.

Returns stored_filename and file_path

pg-boss schedules job for immediate processing

11

12
JOBS → AI

API key decrypted from ai_models record before call
13
AI → JOBS
AI model returns JSON array of extracted scope items
Response may include 0 to N items
14
JOBS → DB

15
UI (polling)

Polling detects completion; terminates poll loop
16

17
MANAGER → UI
Manager reviews/edits items and clicks 'Finalise Scope'
UI collects final items array from table state
18
UI → API
POST /manager/audits/:id/scope/line-items (batch array of line item objects)
API validates each item; inserts into audit_scope_line_items with source='ai_extracted'
19
API → DB
INSERT batch into audit_scope_line_items; INSERT options for MC items into audit_scope_line_item_options; INSERT audit_trail_log entry (action: SCOPE_DEFINED)
All items persisted atomically in a transaction
20
API → UI
Return 201 with created line items array
UI navigates to Scope tab showing full items table; success toast: 'Scope defined — N items added'

3. Flow 2 — Excel Scope Import with Column Mapping
3.1 Overview
Synchronous script-based flow (no Gen AI). Manager uploads an Excel file; the backend auto-detects column headers and suggests mappings; Manager confirms or adjusts; items are imported into audit scope. Two-phase API pattern: upload+detect → confirm.
Attribute
Value
Trigger
Manager selects 'Import Excel' method and uploads .xlsx/.xls file
Preconditions
Audit exists with status=draft; BU selected
Primary Actor
Manager
Async / Sync
Synchronous — all processing inline (no background job queue)
Success End State
Scope line items created from Excel rows; Optional flag set to Mandatory by default
3.2 Step-by-Step Flow
Step
Actor
Action / Event
System Response / Notes
1
MANAGER
Selects BU and uploads .xlsx or .xls file via dropzone
UI validates extension; no size > 10 MB
2
UI → API
POST /scope/import-from-excel (multipart: file + auditBusinessUnitId)
API validates JWT + ownership
3
API
Parse Excel file using SheetJS/exceljs library; read header row of first sheet
Extract column letters (A, B, C...) and header text from row 1
4
API
Run keyword matching against header text: look for 'name'/'item'/'description'/'type'/'method' keywords (case-insensitive)
Build suggestedMapping per column: nameColumn, descriptionColumn, inputMethodColumn, or 'skip'
5
API → DB
Store parsed Excel data in temporary import session: INSERT INTO import_sessions (importId, payload=rows, mappings, expires_at=NOW()+30min)
Session scoped to managerId + auditId
6
API → UI
Return 200: { importId, detectedColumns: [{columnLetter, headerText, suggestedMapping}], previewRows: [first 3 rows raw] }
UI renders Phase 2 column mapping confirmation screen
7
MANAGER
Reviews suggested column mappings; adjusts selects if suggestions are wrong. Views preview rows for reference.
UI tracks user's confirmed mapping in local state
8
MANAGER → UI
Clicks 'Confirm Import' button
UI validates: nameColumn and descriptionColumn must be mapped (not 'skip')
9
UI → API
POST /scope/import-from-excel/:importId/confirm (body: { columnMapping: {nameColumn, descriptionColumn, inputMethodColumn} })
API retrieves import session by importId
10
API → DB
Retrieve import session payload (rows); apply confirmed column mapping to extract Name, Description, Input Method per row
Rows with empty Name or Description flagged as parse errors; remaining rows processed
11
API → DB
Begin transaction: INSERT all valid rows into audit_scope_line_items (source='excel_imported', is_optional=false by default); INSERT options for MC items; INSERT audit_trail_log
Atomic transaction — all or nothing
12
API → DB
Delete import session record (cleanup)
Session removed
13
API → UI
Return 201: { created: [...line items], errors: [{rowNumber, reason}] }
UI renders scope table with imported items; shows error accordion if any rows failed
14
MANAGER
Reviews imported items; adjusts Optional flags as needed; scope is now populated
Manager can edit any item from the scope table (SCR-MGR-007)

4. Flow 3 — Exception Lifecycle
4.1 Overview
End-to-end flow for a scope line item exception: from Auditor raising it, through Manager decision (approve / reject / seek client clarification), to the final downstream outcome on the line item and audit report.
Attribute
Value
Trigger
Auditor clicks 'Raise Exception' on a scope line item
Preconditions
Audit is in_progress; line item assigned to auditor; item not already submitted or excepted
Primary Actors
Auditor (initiates), Manager (decides), optionally Client (provides clarification)
Sync / Async
Synchronous API calls; async via in-app notifications
Outcome A
Manager approves → item flagged in report as exception
Outcome B
Manager rejects → item returned to Auditor for re-submission
Outcome C
Manager seeks client clarification → Client responds → Manager decides

5. Flow 4 — AI Report Generation and Full Review Loop
5.1 Overview
Full lifecycle of audit report creation: from Manager triggering Gen AI generation, through Manager review and editing, client review with structured feedback, and final audit closure. Spans multiple personas and multiple async/sync steps.
Attribute
Value
Trigger
Manager clicks 'Generate Draft Report' when all mandatory items are in terminal state
Preconditions
All mandatory scope items: status = submitted or exception_approved; audit status = in_progress → transitions to under_manager_review on job completion
Primary Actors
Manager (generate, edit, send, finalise), Client (review, feedback)
Async Steps
Report generation (AI job); NL search (covered in separate flow)
Success End State
Audit status = closed; report status = final; all parties notified

6. Flow 5 — Exceptional Action Request (Manager → Admin → Audit Status Change)
6.1 Overview
Flow for Admin-gated exceptional audit controls: a Manager requests deletion of an in-progress audit or re-opening of a closed audit. Admin reviews, uploads evidence, and either approves (triggering audit status change) or rejects. Covers both action types in a single flow with branching.
Attribute
Value
Trigger
Manager opens audit Actions menu → selects 'Request Deletion' or 'Request Re-open'
Preconditions (Delete)
Audit status = draft or in_progress
Preconditions (Re-open)
Audit status = closed
Primary Actors
Manager (requests), Admin (decides)
Success End State — Delete
Audit soft-deleted; all related data retained in DB with deleted_at set
Success End State — Re-open
Audit status = reopened; Manager can modify scope and re-assign auditors
Rejection End State
Audit status unchanged; Manager notified with Admin's rejection reason

Actor
Action / Event
System Response / Notes

MANAGER
Opens audit detail; clicks 3-dot Actions menu; selects 'Request Deletion' (in_progress audit) or 'Request Re-open' (closed audit)
UI shows action type pre-filled in modal (derived from audit status)
2
MANAGER → UI
Enters justification (min 20 chars); clicks 'Submit Request'
